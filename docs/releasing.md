# Releasing

Freilauf is distributed as ready-made installers attached to a GitHub
Release. The installers are built by
[`.github/workflows/release.yml`](../.github/workflows/release.yml) with
[electron-builder](https://www.electron.build/), configured in
[`apps/desktop/electron-builder.yml`](../apps/desktop/electron-builder.yml).

## Cutting a release

The version lives in **`apps/desktop/package.json`** (the root
`package.json` version is not used). Tags are that version prefixed with `v`.

1. **Bump the version** in `apps/desktop/package.json`, e.g. `0.1.0`, and
   commit it on `main` (`Release v0.1.0`).
2. **Optional dry run:** _Actions → Release → Run workflow_ on `main`. This
   builds and uploads the installers as workflow artifacts (kept 14 days)
   without creating a release. Download and try them.
3. **Tag and push:**

   ```sh
   git tag -a v0.1.0 -m "Freilauf 0.1.0"
   git push origin v0.1.0
   ```

4. The workflow runs:
   - `verify` (Ubuntu): fails if the tag is not `v` + the app version, then
     `pnpm typecheck` and `pnpm test`;
   - `package` (Windows, macOS, Linux runners in parallel):
     `pnpm --filter @freilauf/desktop dist`, uploads the installers;
   - `release`: collects all installers, writes `SHA256SUMS.txt` and creates
     a **draft** release with auto-generated notes. Tags containing a `-`
     (e.g. `v0.2.0-beta.1`) are marked as pre-release.
5. **Review the draft** under _Releases_: check that all six files are
   attached (see below), edit the notes (link known issues, mention the
   unsigned-build warnings), ideally install one build per OS, then
   **Publish release**.

If a `package` job fails, fix the cause and _Re-run failed jobs_; the
`release` job then replaces the assets of the existing draft. If the fix needs
a new commit, delete the draft and the tag
(`git push --delete origin v0.1.0 && git tag -d v0.1.0`), and tag again.

## Artifacts

| File                                       | What it is                                                     |
| ------------------------------------------ | -------------------------------------------------------------- |
| `Freilauf-<version>-win-x64-setup.exe`     | Windows installer (NSIS, one-click, per-user, no admin rights) |
| `Freilauf-<version>-win-x64.zip`           | Windows portable build: unzip anywhere and run `Freilauf.exe`  |
| `Freilauf-<version>-mac-universal.dmg`     | macOS disk image, universal binary (Apple Silicon + Intel)     |
| `Freilauf-<version>-mac-universal.zip`     | Same app as a zip                                              |
| `Freilauf-<version>-linux-x86_64.AppImage` | Linux x64 AppImage: `chmod +x` and run                         |
| `SHA256SUMS.txt`                           | SHA-256 of every file above (`sha256sum -c SHA256SUMS.txt`)    |

The Windows installer puts the app in `%LOCALAPPDATA%\Programs\Freilauf`,
adds Start menu and desktop shortcuts and an uninstaller under _Apps_.

macOS is built as **one universal app** rather than separate arm64 and x64
builds: users cannot pick the wrong download, at the cost of roughly twice
the download size. Switching to per-arch builds is a one-line change
(`arch: [arm64, x64]` under `mac.target` in `electron-builder.yml`).

Settings and rides are stored in the per-user data folder named after the
product (`%APPDATA%\Freilauf`, `~/Library/Application Support/Freilauf`,
`~/.config/Freilauf`); uninstalling does not delete them.

## What goes into the package

electron-vite bundles main, preload and both renderers, including the
`@freilauf/*` workspace packages, into `apps/desktop/out/`. The built main
process only imports `electron` and Node built-ins, so the package contains
just `out/**` and `package.json` inside `app.asar` and **no `node_modules`**
(pnpm's symlinked `node_modules` never need resolving). `pnpm dist` runs
[`build/check-bundle.mjs`](../apps/desktop/build/check-bundle.mjs) before
packaging and fails if main or preload import anything else, which usually
means a new workspace package is missing from `WORKSPACE_PACKAGES` in
`electron.vite.config.ts`. If a native or otherwise unbundleable runtime
dependency is ever needed, it has to be added to `files` in
`electron-builder.yml` (and `npmRebuild` turned back on for native modules).

Other packaging details:

- **Icon:** `apps/desktop/build/icon.png` (1024×1024) is a placeholder
  generated by `node apps/desktop/build/generate-icon.mjs` (also writes
  `icon.svg`). electron-builder derives the `.icns`, `.ico` and Linux sizes
  from it. Replace the PNG (or the script) to change the icon.
- **`freilauf://` URL scheme:** registered by the installers (macOS
  `Info.plist`, Linux `.desktop` `MimeType`, Windows registry via
  `build/installer.nsh`; the portable zip and an AppImage that has not been
  integrated into the desktop register nothing). **The app does not handle
  these links yet**: the main process needs a single-instance lock,
  `app.setAsDefaultProtocolClient('freilauf')`, the macOS `open-url` event
  and the URL from `second-instance` argv on Windows/Linux.
- **Bluetooth on macOS:** `NSBluetoothAlwaysUsageDescription` is set in
  `Info.plist` (without it macOS kills the app when it touches Bluetooth), and
  `build/entitlements.mac.plist` grants `com.apple.security.device.bluetooth`
  plus `allow-jit` for the hardened runtime.
- **No auto-update** yet. Future work: `electron-updater`, a `publish`
  provider (GitHub) in `electron-builder.yml`, uploading the `latest*.yml` and
  `.blockmap` files with each release, and signed macOS builds (Squirrel.Mac
  refuses unsigned updates).

## Unsigned builds

There are no code-signing certificates yet, so:

- **Windows:** the installer and `Freilauf.exe` are unsigned. SmartScreen
  shows _"Windows protected your PC"_ with an unknown publisher; users click
  _More info → Run anyway_. Some antivirus products are more suspicious of
  unsigned NSIS installers.
- **macOS:** the app is **ad-hoc signed** (`mac.identity: '-'`), because
  Apple Silicon refuses to run code without any signature, but it is not
  signed with a Developer ID or notarised. Gatekeeper reports that the app
  _"cannot be opened because Apple cannot check it for malicious software"_
  (sometimes _"is damaged and can't be opened"_). Users either right-click
  the app → _Open_ → _Open_ (macOS 14 and older), or try to open it once and
  then use _System Settings → Privacy & Security → Open Anyway_ (macOS 15+),
  or remove the quarantine flag:
  `xattr -dr com.apple.quarantine /Applications/Freilauf.app`.
  The Bluetooth permission may be asked again after each update because the
  ad-hoc signature changes with every build.
- **Linux:** AppImages are not signed; nothing to do. Running an AppImage
  needs FUSE 2 (`libfuse2`, on Ubuntu 24.04+ `libfuse2t64`); without it, run
  `./Freilauf-….AppImage --appimage-extract-and-run`.

### Signing later

electron-builder signs automatically once the credentials are present as
environment variables in the `package` job. Store them as repository (or
`release` environment) secrets and pass them only to the job that needs them,
for example:

```yaml
- run: pnpm --filter @freilauf/desktop dist
  env:
    # Windows (code-signing certificate as base64 .pfx)
    WIN_CSC_LINK: ${{ matrix.platform == 'windows' && secrets.WIN_CSC_LINK || '' }}
    WIN_CSC_KEY_PASSWORD: ${{ matrix.platform == 'windows' && secrets.WIN_CSC_KEY_PASSWORD || '' }}
    # macOS (Developer ID Application certificate as base64 .p12)
    CSC_LINK: ${{ matrix.platform == 'macos' && secrets.MAC_CSC_LINK || '' }}
    CSC_KEY_PASSWORD: ${{ matrix.platform == 'macos' && secrets.MAC_CSC_KEY_PASSWORD || '' }}
```

- **Windows:** an OV/EV code-signing certificate (`WIN_CSC_LINK`,
  `WIN_CSC_KEY_PASSWORD`), or Azure Trusted Signing via `win.azureSignOptions`
  in `electron-builder.yml` with `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`,
  `AZURE_CLIENT_SECRET`. Most certificates sold today live on hardware tokens
  or cloud HSMs, which makes Azure Trusted Signing the easier route in CI.
- **macOS:** an Apple Developer Program membership and a _Developer ID
  Application_ certificate (`CSC_LINK`, `CSC_KEY_PASSWORD`). Then in
  `electron-builder.yml` remove `identity: '-'` and `notarize: false`, and
  in the workflow remove `CSC_IDENTITY_AUTO_DISCOVERY: 'false'`. Notarisation
  needs an App Store Connect API key: `APPLE_API_KEY` (path to the `.p8`
  file — write the secret to a file in a step first), `APPLE_API_KEY_ID`,
  `APPLE_API_ISSUER`. Re-test whether
  `com.apple.security.cs.disable-library-validation` can then be dropped from
  the entitlements.

## Building locally

```sh
pnpm install
pnpm dist                                  # build + package for the current OS
pnpm --filter @freilauf/desktop dist:dir   # unpacked app only (fast)
```

Output goes to `apps/desktop/release/<version>/` (git-ignored). Run the
unpacked build with simulated devices and a throwaway data folder, e.g. on
Linux:

```sh
FREILAUF_SIM=1 FREILAUF_USER_DATA=$(mktemp -d) \
  apps/desktop/release/0.1.0/linux-unpacked/freilauf
```

(`--no-sandbox` is needed when running as root, e.g. in a container.)

Cross-building is limited: on Linux, `electron-builder --win zip` works but
the NSIS installer needs `wine`; macOS builds (dmg, signing) need macOS. Use
the workflow's dry run for the other platforms. electron-builder downloads
Electron and its helper tools (NSIS, AppImage runtime, …) from GitHub on first
use and caches them (`~/.cache/electron`, `~/.cache/electron-builder`).
